# 视频超分实施与验证记录

更新：2026-11-04（Asia/Shanghai）。**源码和真实本地短片闭环已完成；不是安装包已交付或 GUI 人工验收通过的声明。**

## 1. 实际实现

- 左侧新增“媒体工具 → 视频超分”，页面独立于下载任务列表；原生选择输入和输出目录，显示探测参数、模型能力、帧进度、阶段、错误、取消和打开已校验成片入口。
- `packages/shared/src/upscale.ts` 定义独立创建参数、任务/媒体/能力/事件类型，不复用下载字节进度；独立 WebSocket 判别值为 `upscale.updated`。页面以 1 秒任务快照轮询更新，不假造 ETA。
- SQLite schema 从 3 升至 4，新增 `upscale_tasks`，保存任务与临时目录归属；单超分作业并发，最多 10 个运行/排队任务，下载并发独立。重启将遗留运行/排队任务标记为中断，不提供断点续算。
- 本机引擎完全按需运行：FFprobe 先做单次轻量元数据边界检查，随后由逐帧时间戳扫描同时核验实际帧数和 PTS，不再重复执行 `-count_frames` 全片扫描；FFmpeg 顺序 PNG 管道带背压；每批最多 12 张输入/输出 PNG；NCNN/Vulkan 真实推理，tile 256、`1:1:1`；连续 FFmpeg 编码，不拼接分段。H.264 CRF18 / medium / `bf=0`，编码线程 4、解码线程 2、lookahead 8、最大码率 80 Mbps，输出 BT.709。
- 校验精确 2× 尺寸、帧数、原有理数帧率、逐帧 PTS、输出 DTS、视频时长、音轨数量、完整解码与 AAC 压缩数据 SHA-256 后，在目标卷内用硬链接原子无覆盖提交；失败/取消删除本任务中间文件，仅保留数据库错误，不把候选文件作为成功结果。目标文件系统需支持该无覆盖硬链接提交，不支持时明确失败。
- 保留源片，拒绝已有输出、同文件、符号链接和非规范/不可读文件；排队前、运行前、提交前检查源文件身份/尺寸/修改时间。取消与最终提交有线性化边界：提交已开始时取消返回 409，不能把成功文件误标为已取消。
- 本地 API 需要桌面会话令牌；输入/输出选择由原生 HMAC 签名，并换成 10 分钟、一次性的授权引用。纯浏览器服务不开放任意本机路径处理；限制 Host/Origin，保留已有核心校验。解复用强制 MOV/MP4，禁止网络协议及外部 MOV 数据引用，进程参数不经 shell。
- 每个工具有一个随核心分发的轻量 `.mjs` 看护进程，使用已有内置 Node，不增加 Python 或另一个 App。IPC 断开可识别核心被强杀，终止自己创建的工具进程组；这是为解决原生工具没有可靠父进程死亡通知的生命周期边界。看护本身有内存成本，已单独测量；空闲时不保留模型/工具看护进程。

## 2. 支持范围与明确限制

macOS Apple Silicon；本地 SDR、1–60 fps CFR、8-bit H.264 / 4:2:0 MP4，偶数尺寸 64×64 至 1920×1080、最大 10 分钟 / 36000 帧。无音轨或单路单/双声道 AAC，音频须起点为零、时长与视频匹配。明确拒绝 HDR、VFR、旋转/显示矩阵、隔行、非方形像素、其它附加视频元数据、字幕/章节/多轨、未知帧数/时长及超过上限的输入。原片采用全范围 `yuvj420p` 和 BT.601 矩阵，已实际支持；SDR 会解码到 RGB 再转 BT.709，不承诺保留自定义 ICC/描述性元数据，也不是无损修复。普通实拍效果、其它平台/模型未验收。

空间预算包括 12 组输入/输出帧、缓冲及两份保守候选视频容量，每批再次检查；不是“只要 512 MiB 就能跑”。阈值算术与拒绝逻辑经过测试，未真实耗尽用户磁盘。未知规模不启动推理；没有伪造进度或 ETA。

## 5. 真实模型与资源实测

环境：Apple M4、24 GiB 统一内存、macOS 27.0.1。通过隔离 CLI 核心模块运行，不启动桌面应用，不占用现有开发端口。用 `/bin/ps` 每 50 ms 采样归属进程；采样进程与调度开销包含在 CLI 驱动观察内。未独立测量 GPU 分配、共享页或系统总工作集。

## 6. 本轮补充验证与构建准备

- 对任务数据库快照增加 Zod 运行时校验。损坏/不兼容行保留供诊断并跳过，不会因 `JSON.parse` 异常阻止核心启动，也不会依据不可信路径清理目录；合法中断及终态遗留记录仍按任务 UUID 和 owner 标记清理。
- 增加 AAC 每包 PTS/DTS/时长与包数校验；固定来源自构建的 FFmpeg/FFprobe 对短 AAC 样片的输入/输出包时间线比较通过，完整原片此前运行已完成音频 SHA-256 与媒体完整性校验。
- 文件名同时限制 Unicode NFC/NFD 后 UTF-8 字节长度（240 字节），前端和服务入口复用同一 schema，避免字符数不大但超出常见文件系统单组件限制；服务层也不再信任绕过 HTTP 的类型调用。
- 授权耗时为异步操作，创建时在 await 后重新检查队列上限，避免并发请求同时穿过容量检查。异常/超限子进程输出保持在 watchdog 管理下回收；失败时附带最多 2 KiB 的受限诊断，不因父进程强杀看护而遗留工具。
- 授权探测阶段实际创建、硬链接并删除唯一命名的小型检查文件，验证目标卷支持同卷硬链接提交；不支持时在启动推理前拒绝。此检查不是原子无覆盖提交本身的替代品，最终仍用 `link()` 竞争安全提交。
- 新增离线 FFmpeg 源码构建脚本，固定 FFmpeg 8.1、x264 revision、pkgconf 源归档的 SHA-256；目标为精简 FFmpeg + 单独 FFprobe、静态 x264、系统动态库白名单，并保留 GPL/x264 许可证、构建配置和对应源代码归档。实际源码构建成功，`ffmpeg`/`ffprobe` 均为 arm64，动态依赖只有 macOS 系统库，单独拷贝到开发测试目录后 capability 检查与 26 帧静音/AAC/真实取消管线通过。运行时依赖没有 Homebrew 路径。构建脚本不下载、不安装、不写入 staged runtime。仅有构建产物也不构成再分发许可审查。
- 构建脚本回归覆盖系统动态库 allowlist、固定源归档元数据、两种 Tauri 资源布局、未审核哈希在执行输入程序前拒绝、保护已有（含部分准备的）运行资源和拒绝错误参数。开发入口测试覆盖数据/凭据隔离、绝对路径、端口占用时不终止拥有者及不隐式启动。
- 更正早期失败归因：复核执行记录可见，一次全长测试期间验证操作向该测试所属的 FFmpeg 编码/解码进程发送了 SIGTERM，之后记录退出码 255。旧记录将其称为“NCNN 引擎失败、根因未知”不准确；这是受到测试进程干扰的失败记录，不能据此判断 NCNN 存在并发缺陷。保留 `artifacts/upscale-validation/run-1h1GME/report.json`，不计为通过；后续独立完整运行成功。进程错误现明确包含失败工具名，便于区分编码器/探测器/推理工具。

独占全长运行报告：`artifacts/upscale-validation/run-KhQ89d/report.json`。真正的原始 1080p H.264 + AAC 14.08 秒 / 338 帧样本处理为 3840×2160、338 帧，任务状态 `succeeded`，全程 **512.95 秒**，输出 44,244,957 字节；音频压缩数据哈希与音轨完整保留检查通过，源样本前后 SHA-256 都是 `a322c9947e6486c887cdc0ba913bbe57476b230abf45d85d95d86bce3898cfcd`。完整成片位于 `artifacts/upscale-validation/run-KhQ89d/original-4k-full-aac.mp4`。

该次 50ms 采样报告的进程 RSS：驱动进程峰值 308,176 KiB，Real-ESRGAN 峰值 550,848 KiB，同时 FFmpeg 进程 RSS 峰值采样和 1,067,968 KiB，单个 FFmpeg 峰值 954,400 KiB，看护进程合计峰值采样 243,456 KiB，所有被识别的所属进程树 RSS 合计采样峰值 2,036,400 KiB（约 1.94 GiB）。本任务采样到的临时 PNG/候选视频逻辑文件大小合计峰值 175,039,297 字节（约 167 MiB），PNG 数量峰值 24。进程 RSS 可能重复计算共享页，不是物理内存唯一占用或 GPU 专用内存；本数值属于本机 M4/24GiB 环境的实测，不构成固定内存保证，也没有测整个桌面 App。
