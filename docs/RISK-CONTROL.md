# mediaGrab 风险与合规边界

这份文档优先约束产品行为，而不是指导绕过平台保护。平台规则、接口行为和法律要求会变化，发布前必须重新核对目标平台的服务条款与适用法律。

## 1. 不可逾越的边界

- 只处理用户有权访问、保存或转换的内容。
- 不破解 DRM，不绕过付费、地区限制、登录验证或会员权限。
- 不使用账号池、共享 Cookie、他人令牌或伪造登录态。
- 不提供去水印、批量骚扰式抓取、公开代理或多用户 SaaS 能力。
- 不把本地服务绑定到公网；桌面应用的本地 API 只允许本机调用。

## 2. 平台适配器规则

每个 adapter 必须独立维护：

1. 支持的 URL 形态与规范化 ID。
2. 需要的请求头、签名、设备状态和最小请求间隔。
3. 免登录与登录后各自真实可交付的资源。
4. 平台错误码到通用错误类别的映射。
5. 链接有效期、重取流条件和取消行为。

adapter 不得向 UI 暴露 Cookie、签名密钥、完整带参 URL、设备指纹或平台内部错误堆栈。

## 3. 凭据与本地数据

- 默认不登录；设备级缓存和用户账号凭据分开存储。
- 凭据优先使用系统钥匙串；无法使用时加密落盘，文件权限按平台收紧。
- 日志中禁止出现 Cookie、Authorization、签名参数、完整 URL 查询串。
- 数据库和任务临时目录使用系统应用数据目录，不写入源码仓库。
- 用户删除账号或清理数据时，必须同时删除凭据、缓存、任务 manifest 和诊断日志。

当前 Node 核心已实现 B站账号凭据的独立加密保险箱：SQLite 只保存账号元数据，Cookie 使用 AES-256-GCM 加密并以 0600 权限落盘。桌面版若后续接入系统 Keychain / Credential Manager，应通过明确的凭据存储接口集成，不以迁移业务核心为前提。

## 4. 网络与风控

- 解析 API 和下载 CDN 使用不同的并发/限速策略；不能把下载并发用于平台 API。
- 只对网络抖动、超时和明确可恢复错误重试；权限、内容不存在和登录失败不重试。
- 连续风控失败时暂停任务并提示用户，不自动提高请求频率、不切换账号、不伪造浏览器环境。
- 平台返回的“声明支持”不等于当前身份实际能拿到；UI 只能把实际可取资源标为可下载。

## 5. 文件安全

- 所有输出文件名经过平台无关清理，禁止 `..`、绝对路径、控制字符和路径分隔符。
- 临时文件只写入任务目录，完成后使用同一文件系统内的原子移动。
- FFmpeg 通过参数数组启动；用户提供的路径和码率经过校验，不拼接 shell 命令。
- 取消、失败和应用崩溃恢复都要清理或标记临时文件，不能把半成品显示为完成。

## 6. 错误分类

| 类别 | 示例 | UI 行为 |
| --- | --- | --- |
| `invalid-input` | 链接无法识别、分集不存在 | 指向输入或选择项，允许立即修改 |
| `unsupported-platform` | 暂无该平台 adapter | 说明支持范围，不显示通用网络错误 |
| `permission` | 需要登录、会员或无权访问 | 在资源选项上标明，不静默换低质量 |
| `rate-limited` | 平台限流或风控 | 暂停并显示重试时间，不连续点击重试 |
| `expired` | CDN 链接过期 | 重新取流并从已有临时文件续传 |
| `network` | 超时、5xx、断网 | 有限退避重试，仍失败可手动重试 |
| `tooling` | FFmpeg 缺失或转码失败 | 指向设置与诊断，不报告为平台失败 |
| `filesystem` | 无权限、空间不足 | 指向目录和系统错误，保留任务可重试 |

## 7. 变更检查清单

新增平台或下载能力时必须回答：

- 是否有明确的合法使用边界和平台文档依据？
- 是否能在无凭据情况下诚实展示能力边界？
- 是否有请求限速、重试上限和风控暂停？
- 是否有 fixture 测试，且 CI 不访问真实平台？
- 是否有临时文件清理、取消、重启恢复和日志脱敏？
- 是否能在 UI 中解释“为什么不可下载”，而不是只显示 HTTP 失败？
