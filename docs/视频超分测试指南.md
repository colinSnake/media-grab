## 日常使用与状态入口

1. 右上角芯片图标在“新建任务 / 下载队列 / 历史记录 / 视频超分”均常驻，位于 yt-dlp 右侧。点击查看引擎与模型状态，点击状态右侧的刷新图标重新检查；缺依赖、平台不支持或服务断开时显示原因，不因切换页面显示旧就绪状态。
2. 进入“媒体工具 → 视频超分”，选择源 MP4、输出目录并填写名称；地址支持复制，未写后缀自动补充 `.mp4`。选择源视频和目录后自动检查素材，无需另点探测。
3. 检查通过后点击“发起超分”。提交成功清空发起表单，右侧队列保留任务与帧进度；支持取消、按状态筛选及打开成片。删除只移除记录，不删除视频；运行中任务先取消再删除。
4. 状态查询不运行推理；核心重连后自动重新检查，页面切换复用状态。输入范围仍限 macOS Apple Silicon、SDR CFR 1–60 fps 的 8-bit H.264 / 4:2:0 MP4，偶数尺寸 64×64 至 1920×1080，≤600 秒 / 36,000 帧，无音轨或单路单/双声道 AAC；详见实施文档和准入测试。

手工回归时需检查四个页面均能打开芯片详情、刷新和错误反馈，切换页面没有重复图标；同时确认服务断线/恢复状态、原有下载入口和超分自动检查仍正常。常驻图标本身不代表正式发行包包含超分资源，安装包状态以验证记录为准。

## 2. 手动启动开发版

### 日常开发

使用 `pnpm run dev:desktop` 即可启动日常开发桌面。开发核心会优先尊重显式绝对路径 `MEDIAGRAB_UPSCALE_DIR`；未配置时保留已有安装包暂存资源的查找方式，仅在暂存资源缺失且当前为 macOS Apple Silicon 时使用本项目 `.release-tools/upscale-offline-test/` 中已有的依赖。启动日志会打印使用的开发依赖目录，实际可用性仍由核心的 manifest、SHA-256、架构和编解码检查决定。缺少依赖时不会自动下载或伪装可用。

这不会复制开发依赖到发行资源目录，也不会改变日常开发的数据目录或身份验证。启动脚本的环境配置有变更时，需要自行退出并重新执行 `pnpm run dev:desktop`；仅刷新页面无法更新已运行核心的环境变量。

### 隔离验收

先在终端执行以下**只检查命令**：

```sh
cd /Users/ming/Documents/coding/desktop-app/media-grab
pnpm build
pnpm verify:upscale-dev
```

当前工作区已有 `.release-tools/upscale-offline-test/` 开发工具与模型，测试入口会显式将该目录传给核心，不从桌宠项目隐式寻找依赖。其它机器/干净克隆没有这些被忽略的资源；必须自行明确准备，并设置绝对路径 `MEDIAGRAB_UPSCALE_DIR`。工具不会自动下载、安装，也不会把开发 manifest 当作发行审查通过。

确认预检通过后，**由测试者手动启动**：

```sh
pnpm dev:desktop:upscale
```

该命令会编译并启动 Tauri 开发桌面，以及本次拥有的开发核心/Web 服务；不会安装或替换已安装的 MediaGrab。首次编译可能较慢。进入左侧 **媒体工具 → 视频超分**，应显示「本地引擎与模型已就绪」。不要只打开浏览器测试本地文件授权：纯浏览器会被拒绝，这是预期的安全边界。

### 端口与数据安全

- 9067/9070 任何一个端口已被占用时，入口立即拒绝，不清端口、不关闭既有程序。请自行确认占用者，决定是否退出后再试；不要为验收运行 `dev:desktop:clean`。
- 启动时打印新的 `artifacts/upscale-desktop-test-*/` 路径。核心数据库、配置和原生「应用数据目录」共同指向该测试目录，不写已有 `data/` 或已安装 App 的数据目录；原生覆盖只在 debug 编译有效，release 忽略它。
- 每次执行启动命令会新建一套测试数据。需要核对同一次的历史任务时，请保留该目录；本入口不提供自动复用生产数据库。
- 用户在文件对话框选择的输入/输出不属于数据库隔离范围。请用测试片副本、独立输出目录和新的文件名，避免把测试结果混入正式素材。
- 关闭窗口只隐藏到托盘，不等于停止处理；完成后可自行通过托盘退出测试实例，并在终端结束本次开发命令。脚本的信号转发仅面向它创建的子进程组，不按名称杀其它应用。
- 自动预检不启动模型推理；只有创建任务才运行推理工具。短片桌面任务已通过；下面涉及打开结果、取消等尚未逐项确认的交互仍需单独验收。

## 3. 首次验收建议

先用几秒至十几秒的短片，不要第一轮就提交 10 分钟片段。本机 M4/24 GiB 上，同一 14.08 秒 / 338 帧的 1080p 样片曾测得约 7 分 47 秒和 8 分 33 秒两次全长耗时；模型推理速度受运行环境影响，这些数据不是实时播放或 10 分钟片段耗时保证。

支持条件：macOS Apple Silicon，本地 SDR CFR 1–60 fps、8-bit H.264 / 4:2:0 MP4、偶数尺寸 64×64 至 1920×1080，最长 600 秒且不超过 36000 帧；无音轨或单路单/双声道 AAC。音频起点/时长必须与视频匹配。输出目录须可写、空间充足且支持硬链接无覆盖提交（先使用本机 APFS 目录）。

| 操作 | 预期结果 | 人工记录 |
| --- | --- | --- |
| 打开左侧视频超分，再切到下载/历史/设置 | 页面可达、返回后任务仍显示；既有导航布局不被破坏 | 未验收 |
| 选择受支持的短片和独立输出目录，点击「探测与检查」 | 显示真实尺寸、帧率、帧数、时长及音轨说明 | 未验收 |
| 点击「开始 2× 超分」 | 任务独立进入排队/处理，按批次更新帧进度；校验完成前不显示成功 | 未验收 |
| 完成后检查状态与新文件 | 「已校验并完成」，宽高均为原片 2×，帧率/帧数不变；源片未被改写 | 未验收 |
| 点击「打开已校验成片」 | 系统播放器打开新文件；试听全片、片尾及音画同步，比较线条/细节/色彩 | 未验收 |
| 运行中取消（选较长短片，确认已在推理） | 任务变为「已取消」，没有成功成片；任务临时目录清理，工具退出 | 未验收 |
| 创建多个任务，取消其中排队任务 | 单超分并发，其余排队；取消队列项不影响当前作业/下载队列 | 未验收 |
| 使用已存在的新文件名 | 明确拒绝，不覆盖已有文件；可修改名字、重新探测后创建 | 未验收 |
| 选择 HEVC/HDR/VFR/旋转/带字幕或多轨样本 | 探测时明确拒绝，不静默转成受限输出；不要误当成引擎故障 | 未验收 |
| 同时浏览下载/设置，并按需测试下载到独立目录 | 超分与下载任务/进度语义独立；既有功能无回归 | 未验收 |

注意：短片可能处理很快，取消测试请以任务进入真实推理为准。最终原子提交已开始时取消可能明确返回 409，不能把已经提交的成功文件标为取消。授权 10 分钟有效且只能消费一次，创建失败后应重新探测。

如需源片不变的独立证据，可在处理前后分别执行：

```sh
shasum -a 256 /绝对路径/测试原片.mp4
```

只比较哈希；不要将参考项目中已经替换的 4K `startup.mp4` 当作 1080p 输入，也不要运行参考项目的 `--install`。

## 6. 自动化与真实模型回归

先在仓库根目录执行：

```sh
pnpm test
pnpm typecheck
pnpm build
```

这些命令不构建桌面安装包。真实模型回归需使用明确指定的本机开发工具；`MEDIAGRAB_UPSCALE_DIR` 指向工具和模型目录，夹具生成器则需支持 `lavfi` 的 FFmpeg：

```sh
MEDIAGRAB_UPSCALE_DIR=/绝对路径/upscale-dev \
UPSCALER_FIXTURE_FFMPEG=/绝对路径/支持lavfi的/ffmpeg \
UPSCALER_TEST_CASES=synthetic,unsupported,cancel \
pnpm test:upscale:real
```

这组用例覆盖静音/AAC 短片、HDR/VFR/旋转/多轨拒绝及真实推理取消。再用受支持的真实 1080p 样片单独验证 4K 输出：

```sh
MEDIAGRAB_UPSCALE_DIR=/绝对路径/upscale-dev \
UPSCALER_FIXTURE_FFMPEG=/绝对路径/支持lavfi的/ffmpeg \
UPSCALER_REFERENCE_VIDEO=/绝对路径/1080p短片.mp4 \
UPSCALER_TEST_CASES=reference \
pnpm test:upscale:real
```

默认只取参考文件前 26 帧；只有在确认输入为 338 帧、1080p、单 AAC 音轨且有足够运行时间后，才设置 `UPSCALER_REFERENCE_FULL=1` 做历史全长样本回归。不要将报告中的短片耗时线性外推为产品性能承诺。离线搬迁回归见第 4 节。

本机 2026-11-04 的通过记录、耗时和资源采样见[实施与验证记录](./视频超分验证记录.md)末尾“减少素材重复解码并复验”一节。该记录使用的开发资源不具备发行审查状态。

## 7. 安装包构建前门禁

2026-11-06 本机 macOS arm64 图片修补测试包已构建：`apps/desktop/src-tauri/target/release/bundle/dmg/MediaGrab_0.1.1_aarch64_upscale-test.dmg`。稳定性更新包 SHA-256 为 `d427b57064c772f6be641ece2a13798ba8ed58b96ed88b04b632cf3b54a00d6f`，DMG 校验通过。此包仅供本机功能测试，不是发行构建；模型权利链仍未审查批准。模型约 198.4 MiB，`.app` 约 501.6 MiB，DMG 约 301 MiB。修补遮罩限制最多 1,600 万候选像素操作，ONNX CPU 推理使用 2 个计算线程；超复杂笔画会返回提示，而不是无限计算。尚未对 8MP 输入在低内存机器上的完整修补+超分流程做压力验收。

安装后请先完全退出当前占用本地端口 9070 的旧 MediaGrab，再安装并启动测试版。验收图片流程：关闭修补开关确认普通图片超分；开启后在平滑背景和纹理背景各选一处涂抹，查看原分辨率修补预览并确认；提交后检查队列结果为 PNG、尺寸为原图两倍且原文件未变化。记录显卡/机器、图像尺寸、预览耗时和观感。模型只做本地推理，不联网下载。遇到失败或取消时确认没有生成成功成片。请勿把此测试 DMG 当作可公开分发的正式发行包。

**当前发行状态：阻塞。** 仓库没有 `resources/media-tools/darwin-arm64/upscale/` 生产资源；`.release-tools/upscale-offline-test/` 的 manifest 标记 `developmentOnly: true`，禁止用于发行。先完成下列准备，再考虑安装包：

1. 完成引擎、权重、NCNN/Vulkan/MoltenVK、FFmpeg、x264 的准确来源和对应许可/源码义务审查。将审查人、日期、明确批准决定、证据、来源和每个输入文件 SHA-256 写入 schema v1 的 `UPSCALER_REVIEW_MANIFEST`；不能只设置 `redistributionReviewed: true` 而没有可复核依据。发行准备脚本会在执行任何输入工具或创建资源目录之前校验这些必填字段和 5 项输入哈希，但不会验证法律结论本身。详见[第三方依赖说明](./third-party/视频超分依赖说明.md)。
2. 准备与审查清单哈希完全一致的来源二进制、权重、FFmpeg/FFprobe 和实际第三方声明文件。来源、文件哈希或构建配置变化时，重新审查，不复用旧批准。当前开发版推理引擎是 universal binary；仅 arm64 的瘦身发行副本是可选体积优化，不是已完成步骤。若纳入，应保留源哈希、记录转换并对最终签名文件重新验哈希、验能力和跑真实模型回归，详见[开发资源清点](./third-party/视频超分依赖说明.md#本机开发资源清点)。
3. 通过审查后，使用绝对路径显式准备发行资源；脚本拒绝覆盖已有目录，失败后的部分目录也不会自动清除：

   ```sh
   UPSCALER_SOURCE_DIR=/绝对路径/引擎与模型目录 \
   UPSCALER_FFMPEG=/绝对路径/发行ffmpeg \
   UPSCALER_FFPROBE=/绝对路径/发行ffprobe \
   UPSCALER_LICENSE_DIR=/绝对路径/完整声明目录 \
   UPSCALER_REVIEW_MANIFEST=/绝对路径/已批准审查.json \
   pnpm prepare:upscale-tools
   ```

4. 发行前运行 `pnpm verify:upscale-tools --required --require-signatures`。该门禁会验证来源 manifest、哈希、架构、版本、FFmpeg 能力、系统动态库、完整声明和工具签名；失败时不能用普通开发构建冒充超分发行通过。
5. 桌面安装包构建前按仓库 `AGENTS.md` 检查超过 30 天且确定不再需要的构建缓存；先移除 `apps/desktop/src-tauri/target/release/bundle/` 中上次生成的安装包，系统废纸篓可用时优先移入废纸篓。保留 Rust/Tauri 编译缓存及所有运行资源，不清空整个 `target/`。之后再运行 `pnpm build:desktop:release`。
6. 构建后针对真实 `.app` 执行 `pnpm verify:upscale-tools --app /绝对路径/MediaGrab.app --require-signatures`，再做隔离环境下的安装包离线推理、安装/启动烟测及第 3 节人工验收。资源验证脚本不启动 GUI，也不能代替声音、音画同步与画质判断。

签名分两层记录：本地工具签名属于严格超分资源门禁的一部分；App/安装器签名与 Apple 公证是后续发行步骤，可以单独排期，但不能因此省略已签名工具的发行检查。没有完成相关步骤时，分别标注状态，不得笼统写“安装包已验证”。

## 8. 2026-11-09 稳定性与图片真链路回归

默认 `pnpm test` 保持离线单元测试：覆盖模型缺失/损坏、原生库载入失败、预览与任务互斥、HTTP 断开取消、关闭等待清理、磁盘满写入故障注入、已提交文件的存储警告、恢复队列、迟到响应和图片管线拒绝分支。故障注入不是物理写满磁盘实验。

脚本使用随测试进程的 FFmpeg/NCNN/ORT 和本地合成 PNG；macOS 原生 `sips` 仅生成 JPEG 夹具。临时图片、内存库及异常退出用的临时 SQLite 文件均与用户数据隔离，运行后清理；JSON 报告写入 `artifacts/upscale-image-regression/`。覆盖源图哈希保护、精确 2×、选区外像素/Alpha、输出不覆盖、损坏输入、实际超分阶段取消与临时目录回收。可选绝对路径 `MEDIAGRAB_IMAGE_RUNTIME` 指向新包的 `resources/core`，并使用该目录的 Node 启动脚本，以复核真正的随包运行时而非仓库编译产物。

连续运行与推理阶段取消（1–10 轮，默认不重复）：

```sh
MEDIAGRAB_UPSCALE_DIR=/绝对路径/包含manifest的超分工具目录 \
MEDIAGRAB_INPAINT_MODEL=/绝对路径/lama.onnx \
UPSCALER_IMAGE_REPEAT=5 UPSCALER_IMAGE_STRESS=1 pnpm test:upscale:image:real
```

每轮先等待 ONNX 子进程报告实际进入推理，再取消预览，核对监督进程及观察到的原生子进程已退出、专属预览目录消失；随后重新修补并超分、关闭并重建服务、确认历史状态与临时目录清理。报告的 `coreRssBytes` 仅是采样时核心 Node 进程 RSS，不含所有子进程，也不是内存无泄漏证明。

脚本还使用自有合成图片和临时文件数据库，令独立测试子进程在硬链接提交后、成功状态写入前自发 `SIGKILL`，然后启动新服务，验证输出大小/摘要与成功恢复。不杀用户应用进程、不修改真实数据库，不通过占满磁盘模拟故障。默认单测另外覆盖同内容不同 inode、符号链接、篡改摘要、未提交、错误归属和不安全候选路径均不得恢复为成功。

GUI 仍须手动确认：缺模型仅禁用修补；任务运行中生成修补预览提示繁忙；预览时无法画新笔画，可取消预览；关闭/切换后无迟到结果；授权过期后笔画保留且要求重新预览；存储故障出现明确警告和“重新检查”入口。磁盘恢复后点击重新检查，应补写记录并恢复排队；成功输出不能因数据库写入失败而丢失或误标失败。

资源边界：源码在 24 GiB Mac 的 2/4/8MP 合成用例通过，不等同于低内存设备、真实照片修补观感或所有复杂选区通过。暂不开放视频修补；模型授权和正式发行审查仍独立保留。
