# MediaGrab UI Design Notes

## 目标

MediaGrab 是一个高频操作型桌面工具。界面需要优先保证扫描效率、状态识别和可操作性，而不是让颜色本身成为视觉焦点。

本次主题整理参考了 GitHub Primer 一类设计系统的做法：颜色按语义角色组织，组件只消费角色 token；深色和浅色主题分别提供同一组角色的值。这样可以在不改组件结构的情况下修正对比度，也避免某个模块把暗色主题的颜色带进浅色主题。

## 颜色层级

`apps/web/src/styles.css` 中的颜色分为三层：

1. **基础色**：`--bg`、`--panel`、`--line`、`--purple`、`--green` 等，描述画布、容器、边框和品牌/状态色。
2. **语义色**：`--text-strong`、`--text-soft`、`--text-muted`、`--text-subtle`、`--text-faint`，以及 `--icon`、`--icon-muted`、`--icon-accent`。组件文字和图标应优先使用这一层。
3. **组件状态**：选中、悬停、错误、成功等状态通过 `color-mix()` 与主题 token 组合，不在组件规则中重新声明一套主题专属色值。

核心语义约定：

- `--text-strong`：标题、主任务名、输入值等主要信息。
- `--text-soft`：说明文字、资源标题、空状态辅助信息。
- `--text-muted`：导航、辅助控件和不抢焦点的可交互文字。
- `--text-subtle`：标签说明、次级元数据。
- `--text-faint`：占位符、弱提示和非关键信息。不能用于承载唯一状态信息。
- `--icon`：默认可交互图标，必须在当前背景上保持清晰。
- `--icon-muted`：非主操作图标和进度中的中性图标。
- `--icon-accent`：选中态、模块标题图标和强调操作图标。
- `--text-on-accent`：渐变主按钮、媒体覆盖层等强调背景上的文字和图标。

## 对比度与可读性

- 正文和操作文字不使用纯粹的“视觉弱化”来表达层级；弱化应通过字号、间距和背景关系共同完成。
- 浅色主题中的次要文字和图标不能直接沿用暗色主题的高亮色。浅色主题为 `--text-soft`、`--text-subtle`、`--text-faint` 和图标角色提供独立值。
- 图标默认使用 `currentColor` 或继承父级的语义色。只有平台品牌标识、媒体封面覆盖层等确实需要品牌固定色的场景，才允许使用独立平台 token。
- 状态不能只靠颜色区分。下载状态同时使用文字标签、图标和颜色表达；错误/成功提示也保留明确文本。
- 禁止使用 `opacity` 作为常规文字层级方案。透明度会随背景变化，容易在浅色主题下造成不可读文字；只有禁用控件或纯装饰元素可以使用透明度。

## 组件约束

新增组件时遵循以下规则：

```css
.new-component {
  color: var(--text-strong);
  border-color: var(--line);
  background: var(--panel);
}

.new-component svg {
  color: var(--icon);
}

.new-component[aria-selected='true'] {
  color: var(--icon-accent);
  border-color: var(--control-border);
  background: var(--control-selected);
}
```

不要在组件规则中新增 `#xxxxxx`、`rgb()` 或 `rgba()` 形式的文字/图标颜色。需要新增颜色时，先判断它属于基础色、语义色还是状态色，再把深浅主题值放入两个主题 token 区域。

以下内容可以保留独立 token 或固定值：

- 平台品牌标识的固定品牌色。
- 媒体预览图片上的播放按钮、时长浮层等必须压在图片上的覆盖层。
- 纯装饰性的渐变、光晕和图形线条。

## 本次整理范围

- 统一侧边栏、导航、模块标题、输入框、任务列表、设置弹窗和空状态中的文字与图标角色。
- 修正浅色主题下来源标识、任务平台标签、次级信息和空状态图标偏浅的问题。
- 将平台标签和状态标签收敛到 `--platform-*`、`--green`、`--red`、`--amber` 等主题 token。
- 将聚焦、选中、悬停背景改为基于主题 token 的 `color-mix()`，避免同一组件在两个主题下出现反差过大的硬编码色块。

后续做视觉调整时，应优先修改 token，而不是在单个组件末尾追加主题覆盖规则。

## 首页动效

首页“把喜欢的内容，带回本地。”区域使用 SVG 绘制轻量的内容流动场景：媒体卡片沿轨道缓慢漂浮，中心星球和前后分层的行星环表达内容进入本地，内容块底部用层叠山峰补足空间层次。这里不使用 canvas，因为图形数量少、需要响应主题颜色和尺寸，SVG 更容易维护，也不会引入额外的绘制循环。

动效只承担空间填充和产品隐喻，不承载操作反馈，不应抢过链接输入和解析按钮的注意力。所有动画都在 `prefers-reduced-motion: reduce` 下关闭；后续新增首页装饰动画也必须提供相同的降级规则。
