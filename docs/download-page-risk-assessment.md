# MediaGrab 宣传下载页风险初步评估

记录日期：2026-10-29。

本文整理本次关于“是否制作 HTML 宣传下载页、公开推广是否可能被追责”的讨论，供后续设计和发布时参考。本次仅记录评估，没有制作或上线宣传页。

## 1. 评估结论与适用范围

可以继续规划静态宣传下载页，但公开推广存在被平台投诉、要求下架或主张法律责任的可能，不能承诺没有风险。开源、免费、仅供学习或免责声明，都不能单独构成免责依据。

判断重点是软件实际提供什么能力、如何获取和处理内容、页面如何宣传，以及是否取得必要授权。HTML 页面本身的形式不能决定整体行为是否合规。

本次评估基于以下假设：

- 主要面向中国大陆用户。
- 产品为本地桌面应用，页面介绍产品并链接到 GitHub Release。
- 网页自身不提供在线解析、Cookie 提交、云端代下载、内容托管或公开代理服务。
- 当前版本为 `v0.1.0` 预发布，安装包尚未签名或完成 Apple 公证，实机验收仍在继续。

这是初步风险分析，不是正式法律意见，也不是对全部适配器、安装包、许可证义务或运营方式完成审查的结论。若目标地区、收费方式、服务形态或产品能力变化，需要重新评估；正式推广时可由专业律师结合实际实现审查。

## 2. 已有项目约束与本次核对边界

项目的 [风险与合规边界](./risk-control.md) 已明确：

- 只处理用户有权访问、保存或转换的内容。
- 不破解 DRM，不绕过付费、地区限制、登录验证或会员权限。
- 不使用账号池、共享 Cookie、他人令牌或伪造登录态。
- 不提供去水印、批量骚扰式抓取、公开代理或多用户 SaaS 能力。
- 本地 API 只允许本机调用。

以上是设计约束。本次讨论阅读了风险控制和媒体工具分发文档，但没有逐项审计适配器，也没有验证每一种平台资源的获取方式。不能仅凭文档已写明边界，就认定实际实现全部符合。

## 3. 主要风险

### 3.1 著作权、下载授权与技术措施

自己原创、明确获授权的内容，是更适合宣传的使用场景。

公开视频、本人账号 Cookie、已购买会员，都不能单独证明拥有复制、再次发布或其他利用内容的权利。可观看不等于可任意下载和传播；同时，也不能笼统认定所有下载行为都违法，需要结合权利归属、授权范围及具体使用方式判断。

如果功能涉及避开受著作权法保护的有效技术措施，还可能产生独立风险。对是否属于技术措施、是否存在法定例外，应结合具体实现审查，不应在宣传中直接保证“任何内容都可下载”。

### 3.2 平台协议、数据获取方式与竞争秩序

作者授权和平台规则需要分别考虑。即使用户获得作者许可，获取方式仍可能涉及平台协议。

讨论时参考的抖音用户服务协议限制以不正当方式进行爬虫抓取、模拟下载等行为，具体约束需要按使用时有效的协议核对。经营活动中，不正当获取使用平台数据、损害其合法权益，也可能涉及反不正当竞争规则；是否适用需要审查实际行为和影响。

后续应分别核对各平台的访问方式、授权接口、登录权限、请求频率、限流处理和数据用途，不能将一个平台的结论直接推广到其他平台。

### 3.3 宣传文案与帮助侵权风险

免责声明不能覆盖软件实际行为。民法典关于教唆、帮助侵权的规定，以及信息网络传播权相关司法解释，都是需要关注的责任依据；具体是否构成，仍需结合事实判断。

不建议使用以下文案或展示方式：

- “全网任意下载”“会员视频免费下”“破解限制”“搬运神器”。
- 暗示已获平台官方授权、与平台存在合作关系，但实际没有授权依据。
- 使用未经许可的影视内容、创作者作品或账号信息进行演示。
- 承诺“绝对合法”“永不限流”“任何链接都支持”“下载后可随意传播”。

页面应真实描述已验证能力，区分“有适配器”“成功解析”“当前账号有权限”和“已完成下载验收”。

### 3.4 第三方开源工具分发

MediaGrab 的 MIT 许可证不能替代 FFmpeg、LAME、yt-dlp 及其随包依赖各自的许可义务。

当前 Release 已提供对应工具源码和构建记录，这是分发准备的一部分，但不能据此宣称已完成全部许可证审查。完整义务取决于实际版本、编译选项、链接方式、修改内容及分发方式。

宣传下载页应提供清楚的第三方声明、许可证和对应源码/构建记录入口，并保证它们与所分发的二进制版本匹配。相关工程约定见 [媒体工具分发方案](./media-tools.md) 和 [桌面 CI 文档](./desktop-ci.md)。

### 3.5 托管、投诉与网站运营

GitHub 有 DMCA 投诉和下架程序。代码或安装包能上传到 GitHub，不代表已经通过法律审核，也不代表不会收到投诉。

如果用中国大陆服务器或相关接入服务部署独立官网，应根据实际服务类型核实备案等要求；境外托管也不能替代版权、平台授权和其他适用规则的判断。本次尚未选择部署地点或核查具体备案要求。

## 4. 建议的页面定位与内容

建议先采用如实介绍能力的静态下载页。这是降低不必要风险的产品建议，不是免责承诺。

推荐的主文案方向：

> **MediaGrab — 本地媒体工作台**
>
> 为你拥有权利或获得授权的媒体，提供链接解析、下载任务管理和本地文件整理。

建议包含以下内容：

| 页面内容 | 建议表达与依据 |
| --- | --- |
| 产品简介 | 介绍本地工作区、媒体选择、任务进度和历史记录，避免夸大平台覆盖范围。 |
| 产品截图 | 使用自制或明确获授权的演示素材，不展示他人 Cookie 或账号隐私。 |
| 版本与下载 | 标明 `v0.1.0` 为预发布，列出各系统架构对应的安装包。 |
| 验证范围 | 说明已通过的 CI 构建和安装后烟测，以及尚未完成的实机验收。 |
| 安装说明 | 如实说明签名和公证状态，不把系统提示描述为可忽略的无意义提示。 |
| 使用边界 | 提醒用户确认访问、保存和使用内容的权利，不作无限制下载承诺。 |
| 第三方声明 | 链接许可证、工具源码、构建记录及校验清单。 |
| 反馈入口 | 提供问题反馈和权利投诉联系渠道，并明确由谁维护处理。 |

本次建议第一版仅介绍产品并链接现有 Release，暂不加入在线解析、Cookie 提交、云端代下载或用户媒体上传功能。若以后增加这些服务，需要重新评估数据处理、授权和运营责任。

当前下载入口：[MediaGrab v0.1.0 Release](https://github.com/colinSnake/media-grab/releases/tag/v0.1.0)。

## 5. 后续待核对事项

以下是评估留下的待办，不表示已完成，也不自动构成额外审批要求：

- [ ] 核对现有适配器的实现是否遵守项目已写明的权限和技术措施边界。
- [ ] 分别核对各目标平台当前有效的协议和允许的访问方式。
- [ ] 确认页面文案中的每项能力都有实际验证依据，展示素材有合法来源。
- [ ] 核对随包工具的实际编译/链接方式与对应许可证义务。
- [ ] 确认网站托管地区、运营方式和可能适用的备案要求。
- [ ] 确认问题与权利投诉渠道，以及收到有效投诉后的处理方式。

就当前讨论而言，优先事项是核对适配器的真实行为，再让宣传文案与核对结果一致。
