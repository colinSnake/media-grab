# 项目结构与开发规范

本文记录 MediaGrab 当前代码组织、模块边界和后续拆分约定。代码目录是实际实现的依据；本文描述的是当前结构，不代表尚未落地的规划能力。

## 当前工作区结构

```text
media-grab/
├─ apps/
│  ├─ web/                       React + TypeScript 用户界面
│  │  ├─ src/

│  │  │  ├─ api.ts               HTTP API 客户端和错误归一化
│  │  │  ├─ main.tsx             React 挂载和启动主题初始化
│  │  │  └─ styles.css           Web 全局样式与响应式规则
```

## 模块职责

| 模块 | 主要职责 | 不应承担 |
| --- | --- | --- |
| `apps/web/src/App.tsx` | 页面级状态、跨区导航、调用 API、组合工作台区域 | 复杂的单项展示、通用弹窗完整表单、重复任务行模板、直接访问 SQLite |
| `apps/web/src/components/` | 有独立输入/输出边界的 UI 单元及交互 | 自行复制全局任务数据、直接拼装 HTTP 请求 |
| `apps/web/src/api.ts` | URL、请求方法、响应与错误处理 | React 状态、DOM 操作和页面文案布局 |
| `apps/server/src/routes/` | HTTP 参数解析、调用服务、映射响应 | 下载业务编排、SQL 和平台协议细节 |
| `apps/server/src/store/` | 数据库结构和持久化读写 | UI 展示逻辑、业务状态迁移决策 |
| `apps/server/src/services.ts` | 创建并连接服务依赖 | 承载某一具体平台的全部实现 |
| `packages/shared/` | 稳定的跨端领域契约、输入输出 schema | Web 专属类型、服务端运行时逻辑或 UI 组件 |

## 下载队列与历史记录

当前任务在 SQLite `tasks` 表中以统一快照持久化；前端另外保存用户下载文件的最近一次结果，用于区分服务端文件生成与本机下载操作：

- 下载队列展示 `waiting`、`downloading`、`merging`，以及服务端已生成文件但尚未点击下载的 `success` 任务；后者不提前显示成功勾勾。
- `fail`、`stopped` 自动归入历史；`success` 在用户尝试下载文件后归入历史，下载成功显示勾勾，下载失败显示叉叉。历史保留结果、错误/文件名和再次下载或任务重试入口。
- 删除历史记录是显式清理操作；删除不应由“完成”隐式触发，否则会失去下载回执、失败诊断和重试能力。
- 前端队列、历史和新建页最近任务都是同一任务快照的不同视图，文件下载结果保存在浏览器本地；最近任务只展示最新三条，不另存副本。
- WebSocket 更新和轮询都必须按任务 ID 合并快照；终态变化或本机下载结果更新后，界面通过筛选完成队列到历史的迁移。

如果未来要加入归档、容量上限或“清空历史”，应定义明确的产品操作和服务端删除 API，不要让 UI 过滤承担数据删除职责。

## 搜索职责

当前搜索弹窗搜索本机已持久化任务快照，支持标题、输入链接、平台、状态和文件名关键词；不调用网络搜索服务。选择结果跳转到该任务所属的队列或历史视图。未来增加远程媒体搜索时，应另设 API 和独立结果模型，不要将其混入本地任务搜索。

## 文件拆分规则

1. 页面组件负责页面编排。单个区域有自己的状态、重复出现，或拥有一组可单独理解的交互时，拆到 `components/`，并用明确的 props 传递输入和回调。
2. 纯逻辑优先放入 `lib/` 或按领域命名的 hook；保持输入输出明确，避免依赖 DOM 或隐式全局状态，以便单元测试。
3. API 调用集中在 `api.ts`，共享契约集中在 `packages/shared/`。禁止组件自行发明同一接口的响应类型。
4. 服务端路由保持薄层；业务状态迁移放 service，SQL 放 repository，平台差异放 adapter。
5. 按职责和认知复杂度拆分，不机械追求行数。一个文件超过约 300 行时应检查职责是否混杂；超过约 500 行时必须评估拆分，并说明保留单文件的理由。
6. 避免为了“复用”抽象只用一次且没有清晰边界的代码。重复的视图模板和稳定的跨模块规则优先抽取。
7. 每次拆分都保持行为不变，并至少运行受影响包的类型检查和构建；改变队列状态、API 契约或持久化行为时补对应测试。
8. 新模块要使用领域清晰的中文或英文命名，避免 `utils.ts`、`common.ts` 等不断膨胀的万能文件。

## 本次前端边界

- `components/TaskRow.tsx` 统一 compact/detail 两种任务行，状态图标、文件下载、取消、重试和删除动作保持一致。
- `components/MediaPreview.tsx` 展示 B站与通用 extractor 的解析结果，并统一封面、时长、清晰度/资源选择。
- `components/TaskSearchDialog.tsx` 负责本地任务搜索交互和搜索结果展示。
- `components/SettingsModal.tsx` 负责设置与 B站账号表单；页面仍持有数据并处理 API 请求。
- `lib/options.ts` 集中新建任务和设置共用的下载模式选项。
- `App.tsx` 负责工作台流程状态以及各视图组合，不负责重复绘制任务行、解析预览或设置表单。
