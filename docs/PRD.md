# mediaGrab 产品需求

| 项目 | 内容 |
| --- | --- |
| 文档版本 | v1.0 |
| 产品状态 | 架构重启，B 站解析链路已存在，跨平台与下载工作流建设中 |
| 目标平台 | macOS、Windows、Linux |
| 首批来源 | B 站、抖音、小红书 |
| 主要用户 | 需要把公开或自己有权访问的网络媒体保存到本机的个人用户 |

## 1. 产品定义

**一句话**：mediaGrab 是一个打开即用的本地媒体工作台，把多平台链接转换成可选择、可追踪、可管理的本地视频或音频文件。

产品不以“某站下载器”为中心，而以“媒体资产处理流程”为中心：输入链接、识别来源、展示可用资源、创建任务、观察进度、管理文件。

## 2. 范围

### P0：首个可用版本

- 粘贴链接或拖入链接文本，自动识别 B 站、抖音、小红书。
- 展示标题、作者、封面、时长、平台、分集或多媒体项。
- 选择视频+音频、仅视频或仅音频。
- 显示可用清晰度、编码、音质、登录/会员限制和失败原因。
- 创建下载任务，展示阶段、进度、速度、剩余时间、取消和重试。
- 选择保存目录；默认保存到系统 Downloads 下的 `mediaGrab` 目录。
- 任务和设置重启后保留。

### P1：稳定性与效率

- 断点续传、临时文件隔离、失败自动重试、链接过期后重新取流。
- 批量粘贴与队列并发控制。
- 音频导出为 m4a / mp3；视频合并和 remux。
- 系统通知、托盘常驻、打开文件夹、复制文件路径。
- 解析历史、收藏任务、按平台和状态筛选。

### P2：扩展

- 更多平台适配器。
- 字幕、封面、章节和元数据导出。
- 播放列表与频道批量任务。
- 可选登录态和平台账号能力，但不以登录作为基础功能前提。

## 3. 核心流程

```text
输入链接
  -> 平台识别与归一化
  -> 获取媒体详情与资源候选
  -> 选择项目 / 清晰度 / 产物类型
  -> 创建本地任务
  -> 下载视频流 / 音频流
  -> 合并、remux 或转码
  -> 原子移动到目标目录
  -> 任务完成、通知、可打开文件
```

任何阶段失败都必须保留可诊断的错误类别和用户可读文案。下载任务不能因为 UI 重新加载而丢失；取消必须清理临时文件。

## 4. UI 信息架构

### 工作台

首屏只围绕一个动作：粘贴链接并解析。解析框下方展示已支持平台、最近任务和全局状态，不展示内部接口、WBI、数据库路径等开发诊断信息。

### 解析结果

左侧展示封面、来源和标题，右侧展示媒体选项。每个选项明确显示格式、分辨率、编码、音质、文件大小估算和访问限制；默认选择“兼容性最好的可用项”。

### 任务中心

按“进行中 / 已完成 / 失败”分组。每项提供阶段进度、速度、目标文件名、暂停/取消/重试/打开目录等动作。

### 设置

仅展示实际生效的配置：下载目录、并发数、默认产物、音频格式、FFmpeg 状态、平台登录态和隐私/日志开关。高级调试信息放入可展开的诊断区域。

## 5. 验收标准

- 新安装、无账号、无历史数据时，用户可以直接粘贴链接并进入解析结果。
- 用户能在创建任务前知道当前选项是否需要登录、会员或额外组件。
- 下载、合并、转码均能取消；取消后不留下半成品冒充成功文件。
- 应用重启后，未完成任务显示为“可恢复”或“需重试”，不能伪装成成功。
- 同一套 UI 在 1280px 桌面、窄窗口和高 DPI 显示器下不出现内容重叠或按钮溢出。
- 没有平台适配器的链接会得到明确的“暂不支持该来源”，而不是通用网络错误。

## 6. 明确不做

不做账号池、共享凭据、绕过会员或区域限制、破解 DRM、去水印、公网 SaaS、多用户权限系统和未经授权的批量抓取。所有平台能力以公开接口、用户权限和服务条款允许的范围为边界。
