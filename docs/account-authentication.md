# 平台认证过期清理与账密登录评估

评估日期：2026-11-05。

## 本次修复

- 设置弹窗打开、应用重新获得焦点、页面恢复可见时刷新已保存的认证状态；弹窗保持打开时每 60 秒刷新一次，隐藏时不发起刷新。
- B站通过既有账号验证接口核验当前账号。服务端明确返回未登录或凭据缺失时，清除失效凭据、登录状态和输入框中的旧密文。导入的 B站认证被明确判定失效时，立即清空该次输入。
- 抖音、小红书、YouTube 导入 Netscape Cookie 文件时保留其到期时间。已知认证 Cookie 全部明确到期，或不存在已知认证项且文件内的平台 Cookie 全部明确到期时，拒绝保存；已保存的认证在状态查询或供解析器使用时自动清除，并返回 `configured: false`、`credentialPreview: null`。
- 存在有效或没有明确到期时间的替代认证 Cookie 时保留凭据。普通 Cookie 请求头没有到期信息，规范化后的 `0` 表示会话 Cookie，不能推断到期。
- 不再依赖中文错误文案识别失效；API 错误保留业务错误码。网络故障、限流、内容权限或风控不会触发自动清除。
- 失效摘要即便携带旧密文，设置输入框也不会回显。刷新结果只更新已保存的认证，保留用户新粘贴的替换内容；较旧的异步结果不能覆盖新保存的状态。后台验证不能恢复已删除账号或覆盖最新的账号启用状态。
- 抖音、小红书、YouTube 当前保存接口只规范化和加密，不在线验证登录，因此状态文案从“认证成功”改为“已保存”。

没有给其他平台新增远程登录验证接口。仅凭一次 yt-dlp 解析失败无法可靠区分凭据撤销、平台风控、视频下架和访问权限不足，因此不能承诺自动识别没有到期时间的 Cookie 的远程失效。

## 是否改成账号密码

结论：不建议将四个平台统一改成应用内账号密码输入。当前项目没有平台账密登录适配，既有解析链路消费的是网站会话 Cookie；登录方式改变后仍需要把有效会话交给现有解析器。增加两个输入框不能替代获取、验证、更新会话的流程。

| 平台 | 现有链路与可行性 | 建议 |
| --- | --- | --- |
| B站 | 自有 HTTP 客户端与 Cookie 账号核验。账密登录需要单独实现登录流程及验证挑战处理，不能直接复用当前导入接口。 | 如要简化操作，优先调研扫码登录或浏览器登录后获取会话，继续复用保险箱和验证接口。 |
| 抖音 | 使用 yt-dlp 与公开页解析。评估时检查的上游 Douyin/TikTok 提取器没有平台账密登录实现。 | 优先评估用户明确授权的浏览器会话导入；普通账密自动登录另行验证可维护性。 |
| 小红书 | 使用 yt-dlp；评估时检查的上游提取器没有账密登录实现。 | 同上，先改善会话导入，不将“已保存”表示为“已认证”。 |
| YouTube | 上游提取器明确不支持密码登录；上游文档也明确说明 OAuth 登录目前不能用于 yt-dlp，推荐 Cookie。 | 保留 Cookie 会话链路；Google/YouTube API 授权不能直接替代当前下载解析器的登录会话。 |

建议下一步先评估“选择浏览器 → 用户授权 → 仅导入当前平台 Cookie → 加密保存”。yt-dlp 已提供浏览器 Cookie 导入能力，可以减少手动复制；是否能够读取目标浏览器的会话、是否需要系统密钥访问权限，仍需在支持的系统和浏览器上实际验证。不能默认读取所有网站的 Cookie，也不能保存包含其他网站凭据的原始导出文件。

若改为应用内登录，需单独评估官方授权范围、验证码/二次确认和登录页兼容性。当前保险箱为本地 AES-256-GCM 加密文件，并非已接入系统 Keychain；本次未引入账号密码采集或存储。

## 验证

- 服务端回归覆盖到期时间、HttpOnly 记录、会话 Cookie、替代认证、保险箱清除、过期替换被拒绝、B站失效、网络失败保留凭据、删除/启用与后台验证并发。
- 前端回归覆盖输入框渲染、平台切换/重新打开、保留新草稿、保存状态文案及错误码分类。
- 使用隔离的 Chrome 临时配置及模拟 API 检查实际弹窗：后台失效清空、网络失败保留、导入失效清空、三个 Cookie 平台的状态刷新、延迟响应不能覆盖新保存信息。未使用真实平台账号或本机用户 Cookie。
- 已构建 macOS Apple Silicon 本地测试安装包，并在挂载的 DMG 内使用自带 Node 执行内存账号/凭据测试，确认 B站失效认证及到期 Cookie 清理通过；未执行真实账号登录/过期验收。该包包含 developmentOnly 超分资源，不是正式签名/公证发行包。
